- **User-link semantics (as locked in the plan):** nonexistent userId → **400** with
  `errors.userId` (handler-thrown FluentValidation `ValidationException` keyed `UserId`, camel-
  cased by ExceptionHandlingMiddleware); userId already linked to another driver → **409**
  `ConflictException` on POST and PUT (checks exclude self); PUT with null **or omitted** userId
  clears the link (the nullable DTO collapses both — the frontend must always send the current
  link value on edit). Existence (400) is checked before the 1:1 rule (409).
- **1:1 race note:** the link is a handler pre-check only — the approved schema has no unique
  index on user_id (deliberately not added without a checkpoint), so a concurrent-create race
  could double-link. Accepted for v1 (SQLite dev, single-threaded tests).
- **Convention artifact (checkpoint record):** EF Core auto-added a **non-unique**
  `IX_drivers_user_id` backing index for the FK — standard EF convention for every FK, not the
  forbidden *unique* user_id index; the at-most-one-driver-per-user rule stays handler-enforced.
- **Test notes:** seeded user ids are resolved from the login response's `user.id` (the spec's
