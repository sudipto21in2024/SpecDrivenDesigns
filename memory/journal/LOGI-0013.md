- **Evidence chain (how it was diagnosed):**
  1. `git diff --stat fa324bee 50e6602e` (green #10 → first red #11) = **contract + docs + state only**
     — no code/test/workflow change, so the trigger was environmental, not the backend arm.
  2. Run #14 log: base tests pass until 04:35:53, then `POST /api/v1/auth/login` returns **500** and
     every later test dies (`support/api.ts:33` Expected 200 / Received 500; 8 failed, 22 passed).
  3. Run #10 (nominally green) was green **only as flaky**: the same failure appears at
     `warehouses.spec.ts:61` ("waiting for `current-role`", 7.7s) and recovered on retry #1
     (`1 flaky · 29 passed`). So the defect already existed at #10.
  4. Playwright never forwards the API webServer's stdout (only the frontend server's `[WebServer]`
     lines appear) ⇒ CI had **no server-side error text at all**; Serilog's file log was never
     uploaded. That is why five runs produced no root cause.
- **Root cause:** `tests/e2e/global-setup.ts` deleted `e2e-logiflow.db` (+ `-wal`/`-shm`) while the
  API process held them open (Playwright starts webServers *before* globalSetup). On Linux `unlink()`
  succeeds anyway: SQLite keeps writing into deleted inodes and the next physical connection
  re-creates an **empty** file → `no such table …` → HTTP 500 on every request from then on. On
  Windows the delete silently fails because the file is locked — which is exactly why this never
  reproduced locally (local runs were green all along, incl. a clean 30/30 with the old harness).
- **Fix:** the throwaway DB is now prepared **before** the API starts and never touched while it runs:
  - new `tests/e2e/start-api.mjs` (webServer command) removes stale DB/WAL/SHM, then `dotnet run`s the
    API with `Database__ConnectionString=Data Source=<absolute path>`;
  - `playwright.config.ts` computes the absolute `E2E_DB_PATH` (a relative `Data Source` resolves
    against the app's CWD — a silent CI/local divergence) and injects it;
  - `global-setup.ts` no longer removes files; it only resets rows through the API (now also
    `drivers`, 404-tolerant, for the LOGI-0005 qa arm).
  - CI hardening: on failure upload `tests/e2e/test-results` + the API's Serilog `Logs/` +
    `e2e-logiflow.db*` so a red run is diagnosable without re-running it.
- **Gates:** `playwright test --list` 30 tests (config parses) · `node --check start-api.mjs` OK ·
  ci.yml parsed via `js-yaml` (jobs + step names verified) · **local full suite `npx playwright test`
